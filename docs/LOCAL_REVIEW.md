# Локальная версия для просмотра

Технический этап по ТЗ 1–17. Не отправлен на GitHub, не опубликован. Исходная ветка/PR предыдущего этапа не изменялись. Дизайн по утверждённому фото не сохранялся в Figma, не экспортировался и не внедрялся: ждём ответа пользователя утром.

## Изменения

- `js/scene.js`: закрытый объём комнаты, фон/туман, отличимые детали пяти локаций, адаптация кадра; повторяющиеся блоки используют InstancedMesh.
- `js/models.js`: анатомические процедурные модели скелета, слизи, гоблина, шахтёра, стражей/элиты, голема, драугра, пса, дракона и всех исходных боссов. Руки первого лица, оружие в кистях и немедленное обновление при экипировке. Процедурные модели — техническая версия, ещё не окончательная художественная работа.
- `js/item-visuals.js`: единые шесть материальных стилей для моделей и кэшируемых SVG-иконок; инвентарь, магазин, сундук и коллекция используют их. Эпическая редкость оформлена золотом. Доступные комбинации предметов, цены и характеристики сохранены.
- `js/combat.js`: общий игровой таймер для анимаций и событий. Замах/полёт стрелы до HP-урона, отдельный второй удар комбо, движение и замах врагов, реакция/отбрасывание, смерть и однократная награда после неё. Смерть дракона длится 2,8 секунды игрового времени. Огненное дыхание, ограниченная тряска и фиксированный пул из 64 частиц.
- Полная пауза включая замах и смерть; отмена старых событий при новом герое/противнике. Урон и тип текущей атаки фиксируются до смены экипировки на паузе. Кнопка атаки недоступна до окончания ответного удара/возврата.
- Новые модули входят в обязательные проверки загрузчика: при отсутствии файла видны точный путь и HTTP-статус.
- Освобождение геометрий/материалов и instance-буферов. Нет внешних моделей/текстур или новых сетевых зависимостей; ресурсы создаются кодом.

## Проверка

- Smoke: запуск desktop и 390×844, все кнопки меню, новая игра, бой, пауза, возврат из карты/магазина/инвентаря, награда, продолжение/reload, поражение/повтор, повреждённое сохранение, работа без внешних запросов, 404/повтор и отсутствие модуля моделей. Прошёл, ошибок JavaScript 0.
- Regression: повышение уровня, обязательное открытие сундука, экипировка, buy/sell, коллекции, переход босса, финал дракона, продолжение завершённой игры, restart, SDK ready/start/stop на stub. Прошёл, ошибок JavaScript 0.
- Graphics regression: контактный урон, неподвижный замах/HP на паузе, физическая ответная атака, четыре оружия, пауза смерти, одна награда, отмена устаревшей атаки, отдельные попадания комбо (100 → 81 при уроне 10), убийство кровотечением до тяжёлого ответного удара; все доступные редкости и фильтр брони; старый формат сохранения после reload; пять локаций, все 20 исходных ID врагов/боссов, огонь/продолжительная смерть дракона; 30 замен ресурсов и узкий экран. Прошёл, ошибок JavaScript 0.
- После 30 замен в повторяющейся локации: 51 геометрия, 0 текстур, показатели стабильны во всех шести замерах. Конкретное число зависит от экипировки; это не полное измерение CPU/GPU-памяти.
- Headless Edge с программным SwiftShader: 90 кадров, медиана 20,7 мс, p95 20,9 мс. Цель 60 FPS в этом программном режиме не подтверждена.
- Headless Edge с NVIDIA RTX 4060 / Direct3D11: 180 кадров на сценарий, медиана 4,2 мс и p95 около 4,3 мс; обычный бой, отрисовка трёх моделей и 390×844. Запас для 60 FPS на этом ПК есть. Это интервалы RAF в headless браузере, а не подтверждённая частота изображения на физическом экране. Три модели — стрессовая сцена рендера; механика по-прежнему использует одного врага.

Проверки повторяются: `node scripts/smoke.cjs`, `node scripts/regression.cjs`, `node scripts/graphics-regression.cjs`, `node scripts/performance.cjs` (Playwright + установленный Edge/Chrome; переменные PLAYWRIGHT_MODULE/BROWSER_PATH). Перед этим запустить HTTP-сервер 127.0.0.1:8000 из корня. Graphics test делает скриншоты и JSON-отчёт в `artifacts/graphics-review/`.

Галерея фактических 38 скриншотов: `artifacts/graphics-review/index.html` или http://127.0.0.1:8000/artifacts/graphics-review/index.html при запущенном локальном сервере. Каждый кадр подписан. Предметы, характеристики и переходы к боссам задавались тестовым скриптом для покрытия сценариев; это не ручное прохождение 80 уровней и не проверка баланса. Изображения не заменены макетами.
